# Чёрное небо

Стратегия о лесном пожаре в Красноярском крае. Игрок — огонь: он не управляет
юнитами, а покупает эволюции, меняющие константы симуляции. Цель — сжечь больше,
чем в рекордном 2019 году, до прихода осеннего циклона.

Референс — Plague Inc., но карта здесь не декорация: граф соседства из 39
муниципальных округов построен по реальной геометрии OpenStreetMap.

## Запуск

```bash
npm install
npm run dev
```

| Команда | Что делает |
|---|---|
| `npm run dev` | Локальный сервер разработки |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm test` | 18 тестов на данные и симуляцию |
| `npm run balance -- 200 --dist` | Headless-прогон: форма распределения исходов |

## Устройство

```
src/sim/    симуляция, чистый TypeScript без обращений к DOM
src/map/    MapLibre: слои, цветовая шкала
src/ui/     экраны и HUD
tools/      подготовка данных (Python) и прогонщик баланса (TypeScript)
data/       производные данные, читаются игрой
```

Симуляция отделена от рендера не ради чистоты кода, а ради `tools/balance.ts`:
тот же код гоняет тысячу партий без браузера за 11 секунд, и константы
подбираются по распределению исходов, а не на глаз.

## Данные

Всё из OpenStreetMap, готовится один раз скриптами `tools/step1..step4`.
Сырые выгрузки (`data/raw/`) не хранятся в репозитории — они воспроизводятся:

```bash
python tools/step1_list.py       # список округов
python tools/step2_geometry.py   # геометрия границ, возобновляемая загрузка
python tools/step3_build.py      # сшивка колец, граф соседства, упрощение
python tools/step4_attributes.py # население, дороги, реки, аэродромы
```

Граф соседства строится **пересечением множеств way id**: соседние
административные отношения в OSM ссылаются на один и тот же way вдоль общей
границы, поэтому длина общей границы считается точно, без геометрических
операций.

Лесистость и тип горючего — курируемая таблица в `step4_attributes.py`, а не
зональная статистика по ESA WorldCover: последняя требует десятков гигабайт
тайлов 10 м на площадь края. Таблица помечена в коде и заменяется без изменений
в остальном пайплайне.

## Публикация

`.github/workflows/deploy.yml` собирает и публикует на GitHub Pages при пуше
в `main`. В настройках репозитория нужно включить Pages с источником
**GitHub Actions**.
